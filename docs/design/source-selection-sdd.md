## Non-Functional Requirements

| Dimension | Requirement / Design decision |
|---|---|
| Security | Synthetic offerors only; proposal content treated as source selection information — case, buckets and entities scoped to the SourceSelection folder; SAM.gov key (optional) in a secret asset |
| Performance | One agent run per offeror and factor (9 for a 3 × 3 plan) fanned out by a robot; demo batch completes drafting in minutes |
| Scalability | Panel recipients and plan are inputs, so concurrent solicitations run as independent cases |
| Availability / Resilience | Robot entry points are idempotent per solicitation; agent output validated against schema before save |
| Logging & Monitoring | Every finding stores author (agent or evaluator), version and timestamp; Maestro case history plus Data Fabric audit records form the protest trace |
| Compliance | FAR 15.305 / 15.308 — agents draft and cite, named officials rate and decide; every rating traces to a finding and a proposal page |
